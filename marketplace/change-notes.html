0.2.1

修复项：

1、修复自定义提示词未写 {diff}/{fileList} 时模型收不到变更内容、只返回 subject/空 items，导致确认发送后提交框不写入也不提示的问题：现在缺少这两个占位符时会自动追加已勾选文件列表与 diff；空 items 会重试一次，仍为空则写入本地分组结果并明确提示。

2、生成结果为空、任务取消、写入失败或应用结果异常时不再静默返回，总会给出通知；生成请求与结果摘要写入 idea.log，便于排查。

优化项：

1、紧凑重试提示明确要求 items 至少 1 项，减少 JSON 模式下空数组导致的空消息。

0.2.0

新增项：

1、提交消息框新增 Generate Commit Message with Context 动作：可填写关联 issue/PR、补充说明和 Skip CI 预设，生成时一并交给模型；issue 候选会从当前分支名自动预填，并按项目记住上次输入。

2、新增 Format Commit Message 动作：把提交框里已有的消息按当前模板重新排版，保留原有 issue 与 skip-ci 信息；该动作默认隐藏，可在设置中打开。

3、提交面板的三个动作（生成 / 带上下文生成 / 格式化）可分别控制是否显示。

4、新增可复用的 Prompt profiles：支持新建、复制、重命名、编辑、删除，并可选全局默认与项目默认，项目选择优先于全局默认。

5、新增多套提交模板：格式与条目行可编辑，内置 Default 模板受保护、不可删除；支持全局默认与项目默认，选择结果直接用于生成和格式化。

6、新增提交类型及描述维护：类型列表会作为允许类型约束传给模型，减少生成未定义类型的情况。

7、新增 Skip CI 预设（默认 [skip ci]、[ci skip]），可选择追加到消息末尾或放在 subject 前缀。

8、内置英文、中文、日文、韩文界面资源，界面跟随 IDE 语言；生成语言新增日语、韩语，Auto 模式会从历史提交自动识别语言。

9、新增「使用指南」设置页：内置 3 步配置、三个动作说明、提示词/模板占位符表、正确模板值（Format template: {items}，Item line: {text}）、常见误配（把字段标签或 {text} 粘进 Format template）与排错清单；顶部实时显示配置自检结果，并提供一键复制正确值。

10、首次点击提交面板动作时显示一次性引导通知；配置自检发现关键问题时提示并可跳转到使用指南，但不会阻断生成（按用户要求只提示）。同一问题组合每个 IDE 会话最多提示一次，可在通知里选择本次不再提示。

优化项：

1、设置页采用 General、LLM、Commit Content 三个核心标签页：动作显隐、Skip CI、语言与行为、模型连接、prompt/模板/类型分别维护，模板编辑与预览改为可调分栏，长文本区域可滚动；0.2.0 最终扩展为五个 tab（另含项目默认值与使用指南）。

2、提示词模板新增 {types} 与 {extraContext} 占位符；模板未使用占位符时自动追加允许类型与附加上下文，并保留原有的具体化规则，用户已保存的模板不被改写。

3、模型不可用时的本地降级消息支持日语、韩语措辞，不再只用中/英文。

4、带上下文生成时，issue/分支候选的读取放到后台线程完成后再打开弹窗，避免 git 查询阻塞设置/对话框交互。

5、设置入口在 EP 包装下也能稳定显示配置页（不依赖平台对 Configurable.Composite 的展开行为）。

6、设置页由三个标签页扩展为五个：General、LLM、Commit Content、项目默认值、使用指南。原来独立的 [项目设置 - 工具 - Commit Helper] 入口并入第一个配置页的第 4 个 tab，通过项目下拉框选择要编辑的项目；未打开项目时显示提示并禁用编辑。

7、设置页宽度自适应：各标签页内容跟随设置窗口宽度拉伸，不再固定 880px；只保留纵向滚动条，不再出现横向滚动条；Commit Content 的模板编辑/预览分栏随窗口高度伸缩。

8、插件描述、README、Marketplace 描述与 change notes 同步补充初始化配置说明、正确模板示例和排错步骤，用户不必先踩坑才知道字段含义。

0.1.2

修复项：

1、多仓库工程里生成的提交信息只剩"文件名 + 增删行数"：修复前插件把项目相对路径传给 git，IDE 打开的是包含多个 git 子仓库的目录时 diff 为空，模型只能看到文件名；修复后按仓库根相对路径收集 diff，能读到具体代码变更。

2、提交消息框写入多行文本后被裁切、出现滚动条或文字重影：修复前 loading 状态在主线程外切换、写入后未重排，提交框不会随内容变高；修复后 loading/重绘改到 EDT，并在写入后把提交面板自动撑高到完整显示生成内容（最多约占窗口 70%，更长保留滚动条）。

优化项：

1、模型输出预算从默认 1024 tokens 提升到 4096、超时从 60 秒提升到 120 秒：大变更集不容易再因 JSON 被截断而退化成文件清单；JSON 解析失败时会用更紧凑的指令自动重试一次。

2、提示词末尾追加固定"具体化规则"：要求条目写出字段/枚举/接口/配置项的前后变化（例如 upgradeMode 由什么值变为什值），大变更集按行为合并并限制条目数；用户已自定义的提示词模板不被改写，只追加该规则。

3、diff 完全读取不到时给出明确警告：不再静默写入一条只有文件名的本地分组结果。

0.1.0

新增项：

1、提交工具窗口的消息框工具栏新增 Organize Commit Message 入口：把已勾选的文件整理成"首行摘要 + 正文分条"的提交信息，正文按文件/模块分组。

2、生成结果先展示在预览窗，提供"替换 / 追加 / 取消"三个动作；未点确认前不改动消息框内容，也不会触发提交。

3、本地确定性分组加可选模型润色：先按本地规则分组，模型只负责措辞；模型不可用时回退为本地分组结果，而不是报失败。

4、支持三类模型服务：OpenAI 兼容接口、Anthropic、Gemini；接口地址、API Key、模型名可在设置页配置。

5、输出格式模板与提示词模板可编辑，并内置预设。

6、支持读取 .gitmessage / git config commit.template 作为提交信息的输出骨架。

7、支持从当前分支名或最近提交中提取 {issue} 编号并注入提交信息。

8、支持生成 changelog 与 PR 描述，仅复制到剪贴板，不写入仓库文件。

9、提交信息输出支持中文与英文两种语言。
