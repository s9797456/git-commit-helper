Commit Helper

Turns the changes you have checked in the commit panel into a ready-to-commit message: a subject line plus an itemized body. Grouping of files and modules is done locally and deterministically; an optional LLM (OpenAI-compatible, Anthropic or Gemini) only takes care of the wording. If the model is unreachable, the plugin writes the local grouping result instead of failing.

Nothing is generated until you click, and nothing is ever committed for you: the plugin only proposes text in the commit message box, where you can edit it as usual.

Features

  • Three commit-panel actions — Generate Commit Message, Generate Commit Message with Context (issue links, notes and Skip CI) and Format Commit Message (reformat an existing draft with the selected template). Each can be shown or hidden.
  • Hybrid generation — file/module grouping is computed locally; the LLM only rewrites the wording.
  • Reusable prompt profiles and commit templates — create, duplicate, rename, edit and delete them; the built-in Default entries are protected. Global and per-project defaults, with the project selection taking precedence; project defaults are edited in the fourth settings tab.
  • In-IDE Guide and configuration self-check — the last settings tab has a 3-step setup, prompt/template placeholder reference, exact template values, common misconfiguration examples and a live check for empty templates, pasted field labels, {text} in the wrong field, .gitmessage overrides and stale project selections. One-time onboarding notification points to the guide; warnings never block generation.
  • Responsive settings pages — pages follow the IDE window width, avoid horizontal scrollbars and let the template editor/preview grow with the dialog.
  • Commit type management — maintain the allowed types and descriptions used by the model, with Conventional Commit types preloaded.
  • Skip CI presets — configurable markers, appended at the end of the message or as a subject prefix.
  • Repository commit template — an existing .gitmessage / git config commit.template is used as the output skeleton, and its comment lines are preserved.
  • Issue key injection — {issue} is extracted from the branch name or recent commit subjects. No Jira/GitHub API calls.
  • Changelog and PR description — generated in a preview window for copying; no files are written and no git commands are executed.
  • Multi-vendor LLM support — OpenAI-compatible endpoints, Anthropic and Gemini, each configurable, with a local only mode.
  • English, Chinese, Japanese and Korean UI — the interface follows the IDE locale; generated messages can be written in Chinese, English, Japanese or Korean (Auto detects the language from recent history).

Getting started

  1. Open Settings | Tools | Commit Helper. The first time, open the last tab Guide: it has a 3-step setup and a live configuration check. Pick a provider, or stay on Local only (no account needed).
  2. Check the files you want in the commit tool window, click the commit message box, then click Generate Commit Message in its toolbar.
  3. Review the proposal, then replace or append.

Large changesets are sampled and noisy files (lock files, build output, minified bundles, binaries) are summarised instead of being sent in full. Unversioned files are read from disk; files larger than 1 MB are skipped.

Configuration help

The most common setup mistake is pasting the field labels into the inputs. The two template fields are exactly Format template = {items} and Item line = {text}; {text} is only replaced in Item line. Putting it in Format template (or pasting "Format template:" / "Item line:") makes the output contain those literal texts or becomes empty. The Guide tab shows the same explanation, copy buttons and a self-check.

Privacy

Only the diff of the files you explicitly checked is sent to the provider you configured. API keys are stored in the IDE credential store (Password Safe), never in the project. All network access is disabled in Local only mode.

Requirements

  • IntelliJ Platform 2024.1 or newer (IntelliJ IDEA, and any IDE shipping the platform and Git support).
  • Git4Idea (bundled with IntelliJ IDEA and most IntelliJ-based IDEs).
